# Экспертный отчёт по нормативным ссылкам

## Новый отчёт

После обновления проекта доступны:
- **GET** `/api/v1/projects/{project_id}/normative-report` — сгруппированные результаты по **всем документам проекта** с цитатами, страницами PDF, статусами, источником и датой подтверждения, заменяющими стандартами, ссылками на карточки и решениями эксперта;
- страница `http://localhost:5173/reports` — раздел «Экспертный отчёт» с карточками стандартов и действиями эксперта;
- печать из браузера через «Печать / Сохранить PDF» и скачивание JSON.

Отчёт разделяет:
1. **Требуют внимания** — недействующие ГОСТ в нормативных ссылках.
2. **Справочные упоминания** — недействующие ГОСТ из предисловия, библиографии и других справочных частей.
3. **Не удалось проверить** — IEC/EN или обозначения, для которых нет ни локальной записи, ни успешного ответа Росстандарта.
4. **Действующие стандарты** — подтверждённые локальной записью или официальной карточкой обозначения.

Дата `checked_at` — время официального подтверждения статуса. При локальном попадании она берётся из реестра и не подменяется текущим временем; у ручной записи дата может отсутствовать. Для неизвестного статуса есть только `attempted_at`, когда пытались выполнить проверку. Время генерации отчёта не равно дате проверки ГОСТ.

## Как проверить на существующем документе

1. `git pull origin main`.
2. `docker compose up -d --build api web`. Миграция БД `0006` применяется при запуске API. Старые факты, замечания и записи реестра остаются.
3. **ВАЖНО:** для ранее проверенных документов один раз снова вызовите `POST /api/v1/documents/{document_id}/check-normatives`, потому что снимки статусов хранятся отдельно по каждому документу. Если обозначение уже есть в локальном реестре, оно будет использовано без обращения к сайту; для принудительного официального обновления добавьте `?refresh=true`.
4. Откройте `http://localhost:5173/reports`, выберите проект, содержащий этот документ.
5. Проверьте четыре раздела отчёта, цитаты, страницы, официальный статус и заменяющий ГОСТ.
6. При необходимости подтвердите или отклоните замечания. Решение записывается в таблицу `findings` и сохраняется после обновления страницы.
7. Нажмите «Печать / Сохранить PDF» и выберите принтер «Сохранить как PDF» в системном диалоге. Это печатная форма браузера, не серверный генератор PDF.

## Хранение и безопасность

Таблица `normative_verifications` хранит **последнюю попытку** проверки каждого `document_id + code` вместе со статусом, источником (`local`/`rosstandart`), URL и временем подтверждения. При обычной проверке подтверждённый локальный статус используется без сети; `unknown` остаётся только там, где нет ни локальной записи, ни официального ответа. При `refresh=true` и недоступности сайта сохраняется локальная запись с `reason=refresh_failed_local_fallback`. Старые принятые/отклонённые замечания не удаляются: они остаются в истории экспертизы.

До запуска проверки для конкретного документа его старые обозначения в отчёте считаются **непроверенными** с причиной `not_yet_verified`, даже если общий локальный реестр содержит статус. После `check-normatives` локальная запись применяется к этому документу и отображается с `source=local`. Это разделяет результаты разных документов и не скрывает, откуда взят статус.

Для международных IEC/EN подтверждение через российский реестр пока не поддерживается. Отчёт показывает причину `unknown` и не трактует их как недействующие.

Экспертный отчёт помогает находить проблемы, но не является правовым заключением. Факт отмены или замены стандарта сам по себе не означает автоматической обязанности переписывать документ.


## Фильтр документов и раздельные выгрузки

В одном проекте допустимы повторные загрузки одного и того же файла. На странице «Отчёт» теперь есть переключатель **«Отображаемые документы»**:

- **Последняя загрузка** (по времени добавления и ID) — вариант по умолчанию.
- **Конкретный документ** — отображается имя, дата загрузки и короткий ID, поэтому даже одинаковые имена можно различить.
- **Весь проект** — сохраняет прежнюю общую сводку по всем файлам проекта.

Применение фильтра меняет количество и группы стандартов, список цитат, печатную версию и содержимое экспертного JSON, но **не удаляет** другие документы или результаты и не влияет на рассмотрение замечаний всего проекта. Утверждение проекта по-прежнему требует рассмотрения всех замечаний, независимо от выбранного фильтра.

### API

Для всех документов (старый контракт сохранён):

```http
GET /api/v1/projects/{project_id}/normative-report
```

Для одного документа:

```http
GET /api/v1/projects/{project_id}/normative-report?document_id={document_id}
```

Ответ содержит `selected_document_id`: `null` для всего проекта и ID для фильтрованного отчёта. Если документ не относится к проекту, сервер вернёт HTTP 404. Доступных документов можно получить из `GET /api/v1/projects/{project_id}/documents`.

### Экспорт

- **Экспертный JSON (выбор)** — скачивает непосредственно отфильтрованный `NormativeReport` с результатами проверки и решениями эксперта. Больше не включает вторую копию `findings`.
- **Технический JSON (весь проект)** — скачивает прежний технический `GET /api/v1/projects/{project_id}/report` целиком со всеми исходными `findings`. Не зависит от фильтра (это прямо указано на кнопке).
- **Печать / Сохранить PDF** — печатная форма соответствует выбранному документу (или всему проекту) и содержит строку «Область отчёта».

Не путайте число записей по проекту с количеством уникальных стандартов в одном документе: при двух загрузках ГОСТ 32144-2013 старый общий отчёт содержит результаты обеих попыток, а последняя загрузка даёт только результаты новой версии алгоритма.


## Удобные карточки и контекст цитат

- API экспертного отчёта теперь возвращает в каждом `evidence[]` не только проверенную исходную `quote`, но и `context`. Контекст извлекается **непосредственно из исходного текста OCR-фрагмента**, без DeepSeek, максимум около 280 символов. Цитата выделяется маркером; если исходная цитата не встречается дословно, `context=null` и отображается только проверенная цитата.
- В карточке сразу видно **две цитаты**. Остальные раскрываются кнопкой «Показать ещё N упоминаний». При печати браузером **все цитаты выводятся**, даже если на экране были свёрнуты.
- После сводки появились быстрые ссылки на четыре раздела отчёта. Увеличены шрифты метаданных, цитат, статусов и область отображения на широких мониторах.
- Рекомендации для вновь создаваемых замечаний теперь различают **заменённый стандарт с указанной заменой** и **отменённый стандарт без замены**. В интерфейсе исторические замечания показываются с контекстно-правильной рекомендацией, **исходный текст в БД не переписывается** и остаётся доступным в техническом JSON.
- Схема БД и логика проверки обновлены в PR #21: добавлены источник/дата подтверждения и миграция `0006`. Старые отчёты автоматически получают контекст цитат при обновлении страницы из существующих `fragments`; для заполнения `source`/`checked_at` по конкретному документу нужно выполнить повторную проверку.
