# Данные для ручной проверки ТУ ↔ ЗнП

| Папка | Что внутри | Можно ли отправлять в LLM |
|---|---|---|
| `tu-znp/` | Полностью синтетические ТУ/ЗнП, 4 сценария | Да, персональных данных нет |
| `real-tu-2250/` | Транскрипция реальных ТУ + синтетическое ЗнП, 1 сценарий | Только транскрипцию и синтетическое ЗнП; оригинальный PDF — нет |

В каждой папке есть свой `README.md` с ожидаемыми статусами, `scenarios.json` для API и `run_scenarios.py` для офлайн-самопроверки.

```powershell
python docs\manual-test\tu-znp\run_scenarios.py
python docs\manual-test\real-tu-2250\run_scenarios.py
```

Те же сценарии закреплены в `backend/tests/test_requirements_scenarios.py` и входят в обычный `pytest`.

## Результаты локальной проверки

| Режим | Совпало с эталоном | Комментарий |
|---|---|---|
| Детерминированный fallback, embeddings выключены | 31/31 | базовый режим; закреплён автотестом |
| Детерминированный fallback, `fastembed` включён | 26/31 | отличия только `missing → needs_review`: 2 ожидаемых semantic-совпадения `tu-connection` и 3 консервативных срабатывания на отсутствующие пункты; ложных `fulfilled` нет |
| DeepSeek + `fastembed`, сценарий `04` | 7/7 | `tu-fireproofing` корректно `missing` |
| DeepSeek + `fastembed`, `real-tu-2250` | 10/11 | `tu-connection` консервативно `needs_review` вместо `fulfilled` |

LLM-прогоны недетерминированы: таблица фиксирует один локальный запуск, а не гарантированный результат. В fallback без LLM semantic-канал может дать лишний `needs_review` для отсутствующего требования — это осознанно консервативное поведение, не ложное подтверждение.

## Перечни и доказательства

- Если требование ТУ содержит перечень, `fulfilled` возможен только при подтверждении **всех** элементов в пункте ЗнП. Частичное покрытие даёт `needs_review`, а в `reasoning` перечисляются непокрытые элементы.
- Цитата ЗнП должна быть короткой (до 600 символов) точной подстрокой одного пункта. Склеенный список целиком доказательством не считается; fallback выбирает атомарный фрагмент.
- Типографские различия (ёлочки/кавычки, тире, многоточия, неразрывные пробелы) при проверке цитат нормализуются.
- В trace появились `coverage_check`/`evidence_check` (LLM) и шаги `check_list_coverage`/`pick_evidence` (fallback), поэтому ручную проверку можно начинать с них.

Оригинальные подписанные PDF и документы с персональными данными в репозиторий не добавляются. Для внешней LLM их нужно предварительно анонимизировать и согласовать.
