# GREF INDEX: связь с Beget

Этот репозиторий хранит код проекта и команды для GREF INDEX. Сам сайт и MySQL расположены на Beget.

## Первая настройка

1. На Beget замените `api.php` на обновлённый файл (выдаётся отдельно). В API добавлена защита от повторных команд по `requestId` и проверка версии.
2. Убедитесь, что `https://ttvvgg5r.beget.tech/api.php?action=state` открывается по HTTPS. HTTP запрещён: API-ключ не должен передаваться по незащищённому каналу.
3. Создайте **новый** API-ключ на Beget взамен ранее переданного в чат. Не добавляйте ключ ни в коммиты, ни в Issues, ни в описание PR.
4. В репозитории откройте `Settings` → `Secrets and variables` → `Actions` → `New repository secret`. Имя: `GREF_API_KEY`. Значение: новый API-ключ.
5. После попадания workflow в `main`, откройте `Actions` → `GREF INDEX API` → `Run workflow`. Для ручного запуска он только проверяет подключение, ничего не начисляет.

## Как передавать команды

Новый JSON-файл в `.gref/commands/` вызывает workflow после его появления в `main`. Передаются **только вновь добавленные** файлы, не изменённые или старые.

Пример начисления (Руслан всегда имеет 1000 баллов):

```json
{
  "type": "rating",
  "member": "mate2",
  "delta": 150,
  "reason": "Ревью PR #4, разработка схем и моделей требований ТУ и ЗнП"
}
```

`mate1` означает Степана, `mate2` Данила. `delta` может быть от -500 до +500, кроме нуля.

Пример создания задачи:

```json
{
  "type": "task",
  "task": {
    "operation": "save",
    "title": "Реализовать сравнение требований ТУ и ЗнП",
    "description": "Результат в отдельном PR",
    "assignee": "mate2",
    "deadline": "2026-10-25",
    "priority": "high",
    "status": "todo",
    "githubUrl": "https://github.com/Barusss/Sber-Giga-Project/pull/4"
  }
}
```

Чтобы изменить задачу, передайте `id` и все поля через `task.operation=save`. Удаление: `{ "type": "task", "task": { "operation": "delete", "id": 123 } }`.

Каждый файл должен иметь уникальное имя. Повторный запуск workflow с тем же файлом **не применит операцию дважды**: Beget хранит `requestId` в MySQL. Попытка использовать прежний идентификатор с изменённым содержимым завершится ошибкой.

Только события пользователя `Barusss` на ветке `main` имеют доступ к запуску. Не давайте другим участникам право обходить ревью при изменении `.gref/commands/` и `.github/workflows/`.
