## Актуальные сведения для базы знаний

- Документы проходят через fragments и chunks. Атомарные требования извлекаются из fragments, поэтому исправление chunks само по себе не доказывает качество сравнения.
- DOCX не содержит надёжной физической пагинации без рендеринга. Табличные связи сложных сканов пока восстанавливаются неполностью.
- Обычная проверка ГОСТ использует локальный реестр с source=local. refresh=true запрашивает Росстандарт. Сохранённый статус при сбое обновления не выдаётся за новую официальную проверку.
- Анализ ТУ/ЗнП реализован. Поиск поддерживает лексический и опциональный семантический канал FastEmbed. Без LLM автоматическое fulfilled запрещено.
- Результаты, замечания и решения привязаны к паре загруженных документов. Повторный анализ сохраняет решения той же пары; force=true предназначен для их сброса.
- Миграция 0008 добавляет происхождение результатов и записи завершённого анализа. Новое утверждение требует полного непустого анализа и рассмотренных неопределённостей.
- Tesseract остаётся основным OCR; PaddleOCR включается явно. Покрытие слов в OCR-бенчмарке не является WER или recall требований.
- В PR #28 прошли 168 backend-тестов, устранены 14 воспроизведений аудита. Живой DeepSeek и размеченный инженерный набор требуют отдельной приёмки.

## Оставшиеся задания

### Данил

1. Проверить качество извлечения и сопоставления на размеченных ТУ/ЗнП с живым DeepSeek. Включить пропуски, отрицания, перестановку мощностей между объектами, единицы измерения и перефразирование. Результат: эталон, ответы, ошибки, метрики по классам и воспроизводимая команда запуска.
2. Проверить влияние embeddings на качество кандидатов: одинаковые документы и эталон для лексического и гибридного поиска, recall@k, время и ресурсы. Не считать число найденных пунктов показателем полноты.
3. Исправить подтверждённые ошибки модели/поиска по результатам измерений, сохранив проверяемые цитаты и привязку решений к паре.

### Степан

1. Провести регрессионную приёмку dev после PR #28: загрузка → извлечение → ГОСТ → ТУ/ЗнП → решение инженера → отчёт. Проверить повторный запуск, смену пары, пустой анализ и недоступность DeepSeek/Росстандарта.
2. Измерить precision/recall ГОСТ на размеченных реальных PDF/DOCX и сканах. Приложить эталон, ответы API, ложные срабатывания и пропуски; демонстрационные данные test_metrics.py не считать результатом.
3. Проверить интерфейс и печать на ноутбуке и широком экране: длинные цитаты, таблицы, ошибки, local/rosstandart/unknown, выбранная пара в отчёте. Зафиксировать шаги и ожидаемый/фактический результат.

### Руслан

1. Доработать сложные сканы и таблицы на эталонном наборе; проверить повороты, низкий контраст, bbox и разделы. Базовые OCR, PaddleOCR и исправленный выход из оглавления уже реализованы.
2. Вынести долгий анализ в фоновые задания с ограничением общего времени, состояниями выполнения и повторным запуском.
3. Провести финальную интеграционную приёмку в Docker/PostgreSQL, включая миграции до 0008, сохранение решений и отчёты.
