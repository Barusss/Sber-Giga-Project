## Проверить

1. Оба режима по умолчанию выключены: `REQUIREMENTS_EVIDENCE_ID_MODE=false`, `DEEPSEEK_STRICT_EVIDENCE_TOOLS=false`. При выключенных флагах payload, результат matching и targeted не изменяются.
2. При включении режима ID модель видит компактные quote choices, возвращает **только существующие ID**. Python восстанавливает исходные дословные цитаты и повторно применяет старый валидатор источников, непрерывности, числовых параметров и области действия. Неизвестный ID, чужой candidate ID, выдуманный текст, перекрёстная цитата с двух фрагментов или составной parent — не создают `supports`/ `fulfilled`.
3. Слишком длинный/сложный источник или >8 вариантов цитаты **без потери нужных опций** должен вызвать fallback на старый JSON-промпт. Нельзя молча выбросить значимое доказательство, чтобы уместить в лимит.
4. Targeted: отдельные quote-ID пространства для каждого атома; нельзя взять ID одного атома и приписать другому.
5. Strict beta: запрос только при включении обоих флагов, `/beta/chat/completions`, `tools[0].function.strict=true`, forced `tool_choice`, схема закрыта `additionalProperties:false`. Missing tool call, усечённый JSON, неверные поля и неправильное завершение — должны завершаться безопасно, без неявного повтора платного запроса.
6. Checkpoint: переключение формата/strict-флага меняет fingerprint; старые сохранённые ответы не переиспользуются под новой схемой. Pause/resume и лимиты не ломаются.
7. **Контрольная инженерная выборка:** не менее 6 *синтетических* случаев (положительное совпадение, конфликт числовых параметров/единиц, другой объект, неполное покрытие, неизвестный ID, parent scope warning). Проверить отсутствие ложного `fulfilled`; сравнить с legacy при выключенном флаге.
8. **Замер размера:** на 5–10 локальных fake-случаях вывести только агрегат `JSON prompt chars`, `JSON response chars` для legacy и ID mode. Не утверждать экономию токенов по длине символов. Платные actual-token измерения не делать.
