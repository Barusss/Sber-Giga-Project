# План облегчения работы DeepSeek при сверке ТУ ↔ ЗнП

**Согласовано как направление:** 21 ноября 2026. **Статус:** план, не заявление о готовности.  
Сопоставлять с [архитектурным планом масштабирования](TU_ZNP_SCALABILITY_ROADMAP.md) и [уже работающими checkpoint'ами](COMPARISON_CHECKPOINTS_AND_ATOM_RECHECK.md).

## Что уже работает — не делать повторно

- Сохранение каждого успешного DeepSeek `complete_json`, pause/resume, защита от повторной оплаты неопределённого запроса — PR #50. Новых checkpoints для LLM **не требуется**. Для OCR/embeddings — только при подтверждённой проблеме, низкий приоритет.
- Coverage **уже** возвращает `evidence_ids` и Python перепроверяет происхождение ссылок, параметры и область действия. Не переносить это слепо заново; улучшать именно повторную смысловую оценку общего покрытия.
- Поиск кандидатов и проверка дословных цитат, исходных фрагментов, параметров, конфликтов и предупреждений контекста уже существуют. Консервативную проверку нельзя ослаблять ради экономии.

## Волна 1 — небольшие изменения

1. **Компактные ответы matching/targeted по ID дословных исходных цитат.** Python заранее формирует ограниченный список точных непрерывных цитат; модель выбирает ID, Python восстанавливает и проверяет их тем же валидатором. Если цитат для полного выбора недостаточно, безопасно возвращаться к исходному формату. Не подменять выбор смысла одним сходством текстов.
2. **Убрать из повторяющихся запросов дублирующие исходные фрагменты**, сохранив исходный текст, контекст, идентификаторы, условия, числовые параметры и достаточную проверяемую опору. Измерить фактические prompt/completion tokens; не обещать экономию заранее.
3. **Эксперимент со strict function calling DeepSeek** (официальный beta Chat Completions) с флагом, выключенным по умолчанию. Не заменять существующий `json_object` без независимой проверки. Любой невалидный ответ/неизвестный ID — `needs_review`/неподтверждённая связь, не `supports`.
4. **Точечное сокращение coverage-вызовов** только после доказательного анализа, что конкретная проверка уже эквивалентно выполнена. Сейчас модель уже выбирает `evidence_ids`, а Python проверяет их; повторное выполнение после targeted может быть обоснованным. Не делать автоматическое `fulfilled` без смысловой проверки составных условий.

**PR #51:** только пункты 1–3, эксперимент выключен по умолчанию. Пункт 4 — отдельный PR после оценки корректности на эталонных случаях.

## Волна 2 — средние изменения

5. Готовый `Qwen3-Reranker-0.6B` локально, без обучения; сравнить с текущим retrieval и `BGE-reranker-v2-m3` на подтверждённых инженером парах. Не сокращать `top_k` без recall-оценки.
6. Осторожная контекстная индексация: отдельный поисковый контекст и полное доказательное представление. Нельзя заново распространять нерелевантную преамбулу или убирать parent warnings.
7. Матрица покрытий каждого обязательства ТУ: повторно использовать *уже проверенные* отношения, сохранять аудит конфликтов, отдельно направлять сложные составные/условные положения в LLM.
8. **Существующие** checkpoints проверить на больших наборах и сбоях; OCR/embeddings — опциональный локальный cache только при измеренной необходимости.

## Волна 3 — большой рефакторинг, только по итогам измерений

9. Единый двудольный граф ТУ ↔ ЗнП, чтобы не оценивать одинаковую связь платно в двух направлениях.
10. Планировщик только оставшихся смысловых проверок по зависимостям.
11. Экспериментальный каскад дешёвой/дорогой модели после калибровки инженерных ошибок.
12. Параллельные задания только после доказанной идемпотентности и оценки нагрузки.

## Правила принятия

- Сравниваем точность/полноту доказательств, `supports/partial/conflicts`, ложные `fulfilled`, остаток непроверенных обязательств, токены и число вызовов. Ускорение не принимается ценой ложного подтверждения.
- Checkpoint fingerprint обязан отличаться при смене формата промпта/инструмента/модели. Старые результаты не переписывать.
- **Тестирование без денежных и токенных сюрпризов:** CI/pytest + фейковые ответы модели + `httpx.MockTransport`, 0 реальных DeepSeek-вызовов; только компактный набор входных примеров, без полного форензик-прогона. Реальные API-тесты — отдельное явное разрешение.
- Не выводить приватные документы, полные промпты/ответы в отчёт Кодекса. Закладывать ограничение на прочитанные файлы и число итераций.
- Не сливать экспериментальное изменение в `dev` до CI и проверки регрессий: включение флагов — отдельное решение.
