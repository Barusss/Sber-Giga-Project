# Проверка актуальности ГОСТ по Росстандарту

Проверка **не использует DeepSeek для определения статуса**. Источник — официальный портал https://protect.gost.ru/gost, раздел «ГОСТ, ГОСТ Р, ПНСТ». Для каждого ГОСТ с полной редакцией (например, `ГОСТ 29322-92`) backend ищет точное обозначение, загружает карточку и проверяет, что обозначение в заголовке и поле «Обозначение» совпадают. Из карточки читаются статус, название, «Обозначение заменяющего» и URL. Поиск по похожему названию не допускается.

## Как проверить уже загруженный ГОСТ

1. Обновите репозиторий: `git pull origin main`.
2. Запустите `docker compose up -d --build api web`.
3. В `http://localhost:8000/docs` проверьте, что документ уже имеет `normative_reference` через `GET /api/v1/documents/{document_id}/facts?fact_type=normative_reference`.
4. Выполните **POST** `/api/v1/documents/{document_id}/check-normatives` без тела запроса. Для тестового документа, загруженного заново, ID — `e6d34b5f-278b-438b-8807-7c4d50f3dc70`.
5. Ответ содержит `total`, `active`, `obsolete`, `unknown`, `findings_created`, `findings_already_existing` и массив `checked` со статусом, источником, заменой и страницами PDF.
6. Результаты также видны на вкладке **ГОСТ и НТД**: введите ID документа и нажмите **Проверить актуальность**.
7. Откройте **GET** `/api/v1/projects/{project_id}/findings` или отчёт проекта: замечания о недействующих ГОСТ записываются туда с цитатой и ссылкой на официальный источник. У замечаний `review_status=pending`. Повторный запуск не создаёт новых копий.

**Контрольный пример:** официальная карточка ГОСТ 29322-92 — https://protect.gost.ru/gost/details/ddd080ed-1dd3-41bd-8cf7-f55a18dc2c5e . В реестре указан статус «Заменен», заменяющий стандарт «ГОСТ 29322-2014». Если сайт доступен и карточка успешно прочитана, ожидается предупреждение с этим источником и страницами PDF.

## Важные ограничения и поведение

- Только полные обозначения `ГОСТ ...-год` и `ГОСТ Р ...-год` (включая варианты с ИСО/МЭК). Обозначения без года, IEC/EN, СП, СНиП пока получают `unknown`: нельзя безосновательно приписывать им статус из фонда ГОСТ.
- Только `protect.gost.ru` и точные URL карточек `/gost/details/{uuid}`; автоматические переходы на другие сайты запрещены. Входные `source_url` из локального реестра используются лишь как подсказка и при проверке перечитываются в официальном источнике.
- Ошибка сети, изменение структуры официальной страницы, неуверенный результат поиска или неоднозначный статус дают `unknown`. **Кэш локального реестра не выдается за свежую проверку.** Запись в локальный реестр обновляется только при подтверждённом действующем или недействующем статусе.
- `registry_status` хранит буквальную категорию сайта, `status` — `active / obsolete / unknown`. Для «Принят» и «Действует с ограничением» возвращается `unknown`, чтобы не называть стандарт безусловно действующим.
- Замечания `obsolete_normative` создаются при подтверждённом статусе «Заменен», «Отменен», «Срок действия истек» или «Утратил силу в РФ». Ссылка из справочного раздела получает уровень `info`, нормативная — `warning`.
- Повторный запуск не создаёт дубликатов замечаний. Принятые и отклонённые замечания сохраняются для аудита. Изменение статуса ГОСТ не означает автоматическое удаление старых замечаний: их нужно пересмотреть вручную.
- Проверка не требует ключа DeepSeek и не делает вызовов к языковой модели.
- Максимум 50 различных обозначений на один запуск; обработка пока синхронная. У сайта нет подтверждённого документированного публичного API, поэтому используется чтение HTML. При изменении сайта обработчик **перестаёт подтверждать** статусы, а не угадывает их.

Не следует автоматически заменять ссылку только потому, что обнаружена новая редакция. Применимость, требования договора и нормативная обязательность требуют отдельной оценки.

## Тесты

`cd backend && pytest tests/test_normative_verification.py -q`

Сетевые ответы для тестов замоканы через `httpx.MockTransport`. Тесты проверяют извлечение статуса/замены, безопасность адресов, отказ от предположений при ошибках, сохранение и повторную проверку. Работа с живым сайтом проверяется отдельно при запуске у пользователя; успешные unit-тесты не гарантируют сетевую доступность или стабильность HTML-формата.
