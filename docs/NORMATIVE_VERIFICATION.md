# Проверка актуальности ГОСТ: локальный реестр и Росстандарт

Проверка **не использует DeepSeek для определения статуса**. По умолчанию сначала проверяет локальный реестр (включая ручные записи) и возвращает `source=local` без сетевого запроса. При отсутствии записи со статусом `active/obsolete` выполняется проверка на официальном портале https://protect.gost.ru/gost. Ручная запись — **не официальное подтверждение**; её `checked_at` может быть пустой. Кнопка «Обновить из Росстандарта» (`refresh=true`) принудительно запрашивает официальный источник, при ошибке возвращает ранее сохранённое локальное состояние с `reason=refresh_failed_local_fallback`.
 Для каждого ГОСТ с полной редакцией (например, `ГОСТ 29322-92`) backend ищет точное обозначение, загружает карточку и проверяет, что обозначение в заголовке и поле «Обозначение» совпадают. Из карточки читаются статус, название, «Обозначение заменяющего» и URL. Поиск по похожему названию не допускается.

## Как проверить уже загруженный ГОСТ

1. Обновите ветку `dev`: `git pull origin dev`.
2. Запустите `docker compose up -d --build api web`.
3. В `http://localhost:8000/docs` проверьте, что документ уже имеет `normative_reference` через `GET /api/v1/documents/{document_id}/facts?fact_type=normative_reference`.
4. Выполните **POST** `/api/v1/documents/{document_id}/check-normatives` без тела запроса или с `?refresh=true` для обновления из Росстандарта. Для тестового документа, загруженного заново, ID — `e6d34b5f-278b-438b-8807-7c4d50f3dc70`.
5. Ответ содержит `total`, `active`, `obsolete`, `unknown`, `findings_created`, `findings_already_existing` и массив `checked` со статусом, источником, заменой и страницами PDF.
6. Результаты также видны на вкладке **ГОСТ и НТД**: выберите проект, затем документ из выпадающих списков, нажмите **Извлечь** (при необходимости), **Проверить по реестру** или **Обновить из Росстандарта**. Вводить технический ID вручную не требуется.
   Если документ содержит больше пяти уникальных нормативов, проверка продолжится порциями автоматически. Не закрывайте вкладку до завершения; завершённые порции сохраняются.
7. Откройте **GET** `/api/v1/projects/{project_id}/findings` или отчёт проекта: замечания о недействующих ГОСТ записываются туда с цитатой и ссылкой на официальный источник. У замечаний `review_status=pending`. Повторный запуск не создаёт новых копий.

**Контрольный пример:** официальная карточка ГОСТ 29322-92 — https://protect.gost.ru/gost/details/ddd080ed-1dd3-41bd-8cf7-f55a18dc2c5e . В реестре указан статус «Заменен», заменяющий стандарт «ГОСТ 29322-2014». При успешном официальном обновлении сохраняется дата подтверждения. В обычном local-first режиме отображается сохранённый статус с обозначением источника.

## Важные ограничения и поведение

- Только полные обозначения `ГОСТ ...-год` и `ГОСТ Р ...-год` (включая варианты с ИСО/МЭК). Обозначения без года, IEC/EN, СП, СНиП получают `unknown` при отсутствии локальной записи; данные из локального реестра маркируются как `source=local`, без утверждения об официальном подтверждении.
- Только `protect.gost.ru` и точные URL карточек `/gost/details/{uuid}`; автоматические переходы на другие сайты запрещены. Входные `source_url` из локального реестра используются как подсказка при `refresh=true`; в обычном режиме могут возвращаться с источником `local` и **не считаются свежей официальной проверкой**.
- Ошибка сети или неоднозначная официальная карточка дают `unknown`, **если нет пригодной локальной записи**. В противном случае возвращается локальный статус с пометкой источника, старой датой подтверждения (если была) и явным признаком fallback при принудительном обновлении. Кэш никогда не помечается как новое официальное подтверждение.
- `registry_status` хранит буквальную категорию сайта, `status` — `active / obsolete / unknown`. Для «Принят» и «Действует с ограничением» возвращается `unknown`, чтобы не называть стандарт безусловно действующим.
- Замечания `obsolete_normative` создаются при статусе `obsolete` из локального реестра или подтверждённом официальном статусе «Заменен», «Отменен», «Срок действия истек» или «Утратил силу в РФ». Ссылка из справочного раздела получает уровень `info`, нормативная — `warning`.
- Повторный запуск не создаёт дубликатов замечаний. Принятые и отклонённые замечания сохраняются для аудита. Изменение статуса ГОСТ не означает автоматическое удаление старых замечаний: их нужно пересмотреть вручную.
- Проверка не требует ключа DeepSeek и не делает вызовов к языковой модели.
- Проверка больших документов выполняется **порциями**, по умолчанию по 5 различных обозначений, максимум 10 на один HTTP-запрос. Endpoint `POST /api/v1/documents/{document_id}/check-normatives?offset=0&limit=5` возвращает `document_total`, `offset`, `next_offset` и проверенные нормы в `checked`. Для следующей порции используется `next_offset`; если оно `null`, документ обработан. Поле `total` показывает **количество элементов текущей порции**, не всего документа. Перед повторным запуском важно не изменять состав извлечённых нормативов, иначе индексы сместятся. У сайта нет подтверждённого документированного публичного API, поэтому используется чтение HTML. При изменении сайта обработчик перестаёт **подтверждать новые статусы**, но может выдать сохранённые локальные статусы с честным указанием источника.
- На странице «ГОСТ и НТД» достаточно один раз нажать «Проверить по реестру» или «Обновить из Росстандарта». Она автоматически последовательно обрабатывает все порции, показывает «Проверено N из M» и накопленный результат. После остановки или сетевой ошибки можно нажать «Продолжить проверку» и не повторять уже завершённые порции. Каждая порция сохраняется в БД отдельно. Поскольку обращения к официальному сайту выполняются последовательно, длительность полной проверки большого документа может быть значительной.

Не следует автоматически заменять ссылку только потому, что обнаружена новая редакция. Применимость, требования договора и нормативная обязательность требуют отдельной оценки.

## Тесты

`cd backend && pytest tests/test_normative_verification.py -q`

Сетевые ответы для тестов замоканы через `httpx.MockTransport`. Тесты проверяют извлечение статуса/замены, безопасность адресов, отказ от предположений при ошибках, сохранение и повторную проверку. Работа с живым сайтом проверяется отдельно при запуске у пользователя; успешные unit-тесты не гарантируют сетевую доступность или стабильность HTML-формата.

## Совмещение с порционной обработкой, ноябрь 2026

Важное отличие от раннего PR #21: ограничение 50 нормативов **не возвращается**. Статусы проверяются порциями `offset/limit` (по 5, максимум 10), включая `refresh=true`. Кнопки работают с тем же механизмом остановки и продолжения. После частичной ошибки может быть повторно проверена оставшаяся порция; уже созданные замечания не дублируются. Одна порция = одна транзакция БД.

Источник `local` — не доказательство актуальности ГОСТ на сегодняшнюю дату, даже когда локальная запись содержит старую официальную ссылку. Для этого необходим успешный принудительный запрос.
