Дата эксперимента: 21 ноября 2026 года.  
Проверенный живым DeepSeek коммит: `fe0f4a30f3c61aaa24207edc10377aa88a963135`.  
Статус: **DO NOT MERGE до повторной независимой проверки исправлений и области наследования контекста**.

## Что было проверено

Codex проверил исходную пару DOCX, используя production-извлечение,
`ZnPFirstAgent._judge` / `_judge_targeted`, `restore_link_quotes` и
`_validated_link`. Full-run, семантическая атомизация и аудит всех обязательств
не запускались. Это **одиночные сопоставления одного атома с одним кандидатом**,
а не доказательство качества на всём документе.

Зафиксировано **12/12 разрешённых реальных HTTP-попыток**, все HTTP 200,
0 сетевых ошибок, 0 повторов. Бюджет исчерпан; дополнительные вызовы только
после отдельного разрешения пользователя. Сырые документы, промпты, ответы,
ключи и диагностика остаются локально в игнорируемом каталоге.

Использованы четыре исходных сценария:

- A: техническая строка с идентичными параметрами — supports в проверенных
  режимах; это не равно `fulfilled` всего требования.
- B: обмен и каналы связи — partial; реальный надёжно связанный
  родительский условный контекст **не удалось подтвердить**.
- C: разные технические объекты и напряжения — legacy не нашёл связи,
  compact выдал только partial, а Python отклонил его для покрытия:
  `params_match=false`, `scope_consistent=false`.
- D: неполное доказательство — partial.

В проверенных реальных ответах 11 предложенных связей, все 11
приняты проверкой исходных цитат. Отрицательные случаи неизвестных ID,
смешанных цитат, неверного объекта, сетевых ошибок и неполного strict JSON
проверялись отдельно **без платных запросов**, через production-валидаторы,
MockTransport и тестовую PostgreSQL.

## Обнаруженные дефекты и исправления

1. Родительские `context_sources` отсутствовали в compact matching.
   Исправлено ранее в PR #51: контекст передаётся matching и targeted,
   условные ограничения на стороне Python понижают supports до partial.
2. Флаги `false/false` изменяли fingerprint старых checkpoints. Исправлено
   ранее: оригинальные хэши `dev` при выключенных флагах совпадают;
   восстановление ранее оплаченного ответа выполняется без HTTP.
3. `ReadTimeout` и `RemoteProtocolError` автоматически повторялись.
   Исправлено ранее: максимум одна HTTP-отправка, затем явное подтверждение
   риска повторной оплаты, если response не сохранён.
4. Strict принимал неверные `tool_calls.type` и неполные аргументы.
   Исправлено ранее: обязательные поля, типы, enums, nested JSON и
   дополнительные поля проверяются локально.
5. **Дополнительный дефект после реальной проверки:** внешний
   родительский контекст с «либо/или», «не» или «запрещено»
   ошибочно разрешал `supports`. Исправление добавлено в PR #51
   **после** оплаченных испытаний, регрессии проверяют шесть форм условий
   плюс контрольный случай без условий. Отсюда **нет live-доказательства**
   для исправленной версии, только бесплатные тесты.

## Оставшаяся блокирующая архитектурная проблема

Из исходной пары был найден посторонний родитель из более ранней таблицы,
с совпадающим номером. Его `context_sources` передаётся даже при
несоответствии реальной области действия; `context_scope_requires_review`
сохраняется. Это не проблема режимов ID/strict, а возможная ошибка
**глобального накопления `previous_clauses` в атомизации**.

Требуется отдельно доказать правильность применения родительских пунктов
в пределах раздела/таблицы, включая повторную нумерацию и неизвестную
область действия. До этого безопасно сохранять ручную проверку и не
объявлять `fulfilled` на ошибочном или непроверенном контексте.
Не «лечить» этот дефект удалением warnings или родительских цитат.
